I was most impressed by Google Cloud because of its strong focus on artificial intelligence, machine learning, data analytics, and Kubernetes. AWS, Azure, and GCP are similar because all three provide on-demand computing, storage, networking, databases, identity and security services, and tools for building scalable applications. They also use regions and zones to help customers design reliable cloud systems and provide web consoles and command-line tools for resource management. Business requirements strongly influence cloud platform selection because a company must consider budget, existing technologies, performance, security, compliance, geographic reach, and the skills of its IT staff. For example, Azure is a natural choice for an organization already invested in Microsoft technologies, while GCP can be especially attractive for AI and Kubernetes workloads, and AWS is a strong general-purpose option with a broad service portfolio. Acting as a Cloud Solutions Consultant taught me that choosing a cloud provider is not simply about selecting the most popular platform; the decision should match the client's actual technical and business requirements. I also learned how equivalent services can be compared across providers, which makes it easier to evaluate multi-cloud options. My GitHub Cloud Computing Portfolio improved because the work is organized into a dedicated laboratory folder with research files, comparison tables, client recommendations, a decision matrix, screenshots, and a reflection. This activity helped me connect cloud theory with practical decision-making and technical documentation.
